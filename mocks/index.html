monorepo

An ultra-lightweight dev toolbox that lives in your project. Document, track, and prompt your codebase to completion with no cloud or external services.

Unified web interface with an embedded autonomous developer agent, entirely backed by plain markdown files in your repository.

Why dk?

Traditional ticketing systems (Jira, Linear) and documentation engines (Confluence, GitBook) separate your codebase from your issues. dk joins them directly in your project. It’s perfect for solo devs and teams who commit their issues alongside their codebase.

Quick Start

# 1. Clone your project
git clone git@github.com:synlace/monorepo.git
cd monorepo

# 2. Boot up the unified dev platform
export AI_API_KEY=sk-...
just dk     # → http://localhost:8000

Project Structure

Your docs and tickets live entirely in raw markdown. You own your data. 

monorepo/
├── app.py          # FastAPI web server + asyncio agent loop
├── docs/           # your document hierarchy (.md files)
├── tickets/        # your tickets (.md files with frontmatter)
├── templates/      # elegant Jinja2 layouts
├── AGENTS.md       # the exact prompts directing your dev agent
└── justfile        # simple developer recipes

Zero-Mutation Interface

Humans do not modify pages or tickets directly here. This viewport is entirely read-only. All creations, task updates, and modifications are triggered via the **Agent Chat** on the right. This keeps your logs perfectly structured and your updates intentional.

Engineering Docs

System Architecture

dk is crafted as a single, zero-dependency Python process. It reads, parses, and renders files dynamically on every page load to guarantee absolute consistency with your workspace.

Core Stack

  • FastAPI — Handles synchronous page routes, static files, and streaming Server-Sent Events (SSE) for agent chatter.
  • Jinja2 Templates — Renders HTML on the server. Zero client-side JS framework required for blazing-fast loads.
  • Python-Frontmatter — Parses issue metadata (YAML) directly from your markdown ticket files.
  • Markdown Parser — Compiles markdown files to rich HTML on demand.

The Human-Agent Data Loop

By relying on plain markdown files as the database, we allow perfect local development collaboration: 

[Developer] ─→ Type instruction in Chat ──→ [FastAPI Agent]
                                                    │
[UI Updates] ←─ Watch File Changes 🗃️ 🧩 ←── Writes to disk (.md)

Agent Capability & Toolset

The agent runs in-process using an async loop. It can query the state of your project, build documents, and manage ticket pipelines with highly focused, deterministic tools:

  • read_doc(path) — Pulls documentation source file.
  • write_doc(path, md) — Overwrites or creates documentation files.
  • list_tickets() — Scans frontmatter on all files inside tickets/.
  • create_ticket(data) — Saves new ticket markdown with formatted YAML header.
  • update_ticket(id, changes) — Safely updates frontmatter without losing details.
Reference Guide

API Reference

dk features a lightweight local REST API to let you query documentation and ticket databases programmatically, or hook them into pre-commit scripts.

Get All Tickets

Retrieves a listing of all registered tasks, compiled on the fly.

GET /api/tickets
Response: 200 OK
[
  {
    "id": "001",
    "title": "Auth token refresh fails silently",
    "status": "in-progress",
    "priority": "urgent",
    "assignee": "alice"
  }
]

Add Ticket Comment

Appends comments directly inside a ticket's markdown body.

POST /api/tickets/001/comments
Body: { "body": "Checked logs. Looks like a token expiry bug." }

Trigger Agent Prompt

Streams responses directly from your configured LLM model (Local or API).

POST /api/chat
Body: { "prompt": "Review open tickets and propose next steps" }
DevOps Manual

Deploying the Platform

As a local utility, dk requires no heavy server hosting. Running it within your local network allows other developers to browse tickets directly.

Running on Host

Simply let uvicorn launch on your local host:

just dk --host 0.0.0.0 --port 8000

Integrating LLMs

Choose between premium commercial endpoints or completely offline execution:

  • Anthropic (Recommended) — Best logical reasoning for docs. Set export ANTHROPIC_API_KEY=sk-ant-....
  • Ollama — Runs entirely local. Set export AI_MODEL=ollama/llama3.2. No data ever leaves your computer.
Operational Runbook

Operational Runbook

Troubleshooting strategies and useful terminal helpers to maintain your local environment.

Port Conflict

If port 8000 is occupied, find and terminate the active process:

lsof -i :8000
kill -9 <PID>

Forcing Ticket Sync

If you modified ticket markdown files on disk using your text editor, simply click refresh in the browser. The FastAPI server reads directly from the filesystem on every single transaction, meaning zero cache synchronization delay.
